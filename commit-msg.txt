jsdom is a tool, not a dependency — and design/ is history, not authority

Two documentation defects, both found by SOL's reading, both smaller and larger
than it said.

**jsdom.** `package.json` declared it under `dependencies` while README.md says
the game has none. SOL called the README wrong; it is not. The *Measure it*
section already says exactly the right thing — *nothing to install, smoke.js will
use jsdom for the interface checks if it is present and skip them if it is not* —
and that is what the code does. The error was entirely in `package.json`, which
declared a headless-test tool as something the project depends on to run. Moved to
`devDependencies`, with `private: true` so nobody can publish it by accident. The
*Play it* line now also says why the game needs nothing: classic scripts rather
than ES modules, so they load over `file://`.

**The one that actually misleads, and SOL was right about it.** README.md's
repository table called `design/` *the source of truth*, while `design/rules.md`
opens by saying, bluntly and in a box, that **`engine/constants.js` is the
authority and this document is the history**. A reader who trusts the README goes
to the wrong file and quotes dead numbers — which is precisely the failure A-16
was, and precisely what the note in rules.md exists to prevent. What SOL did not
credit is that rules.md already says this about itself and already names the
rewrite as the outstanding debt on the file; the contradiction was one line in the
README, not a design problem. Fixed there, pointing at the note.
